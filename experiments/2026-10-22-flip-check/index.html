Results of run 1: the known-good check failed on fez, kingston and marrakesh

On this page, brackets are 95 % intervals from a 2000-draw bootstrap over qubits (analyze_flip.py).

Read by the committed analysis (full output). Jobs: fez dbd00jhgv2cc738h49ng, kingston dbcvu6s24mrc73ckgfcg, marrakesh dbcvvcpgv2cc738h4770 (fire log, and job records flipjob_ibm_*.json in this folder).

  • Known-good: FAILED on ibm_fez, ibm_kingston and ibm_marrakesh. The flip failure of an idle qubit should sit at the calibration floor. It sat above it at every one of N = 0, 4 and 8: fez +0.61, +0.53, +0.62 percentage points, kingston +0.50, +0.48, +0.48, marrakesh +0.97, +1.01, +1.02 (every interval above zero, full output). The calibration step itself passed on all three (flip success 97.05, 97.44, 97.60 %).
  • One cause, found in the committed plan for run 2: the floor was built from heralded shots (first read verified 0) while the idle arm used all shots, so thermal population sat in one and not the other. The readout arm of the decision reading had the same asymmetry. Run 2 builds the floor like for like, and kingston’s known-good check still fails there (+0.1541 and +0.1835 percentage points above the floor at N = 0 and 4), so this asymmetry accounts for part of run 1’s failure at most.
  • Decisions: void. The analysis printed decision lines anyway (the printed output reads “excluded” for kingston at 8 readouts, and is not used). Under the plan’s own rule a failed known-good makes those readings cannot tell, and run 1’s decisions are void. Where it printed them, the loss with every wired neighbour verified 0 and flipped is above zero on fez at 4 readouts (+0.0039 [+0.0002, +0.0097]) with the copies disagreeing, and consistent with zero at 8 readouts on fez.

So run 1 neither confirms nor excludes a neighbour hidden in a level that reads as 0. Run 2 builds the floor like for like (unheralded in both arms). Its plan, code and synthetic tests were committed before its job, and it was fired on ibm_kingston on 22 October at 09:58 (job dbd1cqfi0auc7394gq30). Its result is on the run 2 page. Measured neighbours stuck in 1 (0.4 to 1.1 % of shots) are a separate cause that this test does not address and that is not excluded.
